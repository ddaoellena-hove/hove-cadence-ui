# Pattern — Liste / index

**Quand l'utiliser** — lister et parcourir un ensemble d'objets (recherche, filtres, sélection, pagination). **Ne pas confondre avec** — Liste + détail latéral (ouvre un `Drawer`), Page de détail (un seul objet).

## Anatomie

```
PageHeader (h1 + action « Créer »)
FilterBar (recherche · filtres rapides · chips actives · actions)
DataTable (tri · sélection · emptyState)
[ BulkActionBar ]  (si ≥ 1 ligne cochée : flottante en bas de la zone visible)
Pagination
```

## Variantes
`DataTable` (gros volume) ou liste de `TableCard` (éléments riches, peu nombreux).

## États
Chargement (`loading` → squelettes), Vide (aucune donnée) et Sans résultat (filtres trop restrictifs) via `emptyState` (`EmptyState variant`), Erreur de chargement.

## Comportements
Les filtres ramènent en page 1 ; les chips actives reflètent les filtres ↔ URL côté app. La sélection fait apparaître la `BulkActionBar`, collée au bas de la zone visible tant que la liste défile.

## Responsive
`DataTable` défile horizontalement si besoin ; `FilterBar` se replie.

## Accessibilité
`main`/`nav` nommés (coque), un seul `h1`, `DataTable` en vrai `<table>` nommé.

## Règles
- ✅ États vides via `EmptyState` (`empty` / `no-results`), jamais à la main.
- ❌ Pas de pagination maison : `Pagination`.
